Why it exists

Logitech's own software is Windows-only and everything else out there is old, abandoned or half-broken, so this talks to the keyboard directly. The LCD is written through a hidraw device that the kernel's own hid-lg-g15 driver keeps owning, instead of detaching the keyboard's extra-keys interface the way g15daemon does, so media and volume keys keep working while the LCD runs.

Features

One app for setting things up; small background services that keep running after you close it.

🧩 Custom screens, edited live

L1 is built in. L2–L5 are yours: open the Custom Screens tab, pick a screen and drop things on it.

  • Sensors as a number or a bar, in different text sizes
  • Text labels, images (converted for the 1-bit screen; flat logos work best) and a visualizer
  • Drag to move; hover a bar's end or an image's corner to resize
  • Up to 8 sensors, 2 images, 4 text fields and 1 visualizer per screen
  • Every change saves itself instantly, no Save button needed

The preview is drawn by the same program that drives the LCD, so it matches the real screen pixel for pixel.

🎵 A little Winamp on your keyboard

Drop a visualizer onto any of L2–L5 and the LCD becomes a tiny live equalizer next to the song title, artist and a running 1:23/3:45.

  • Listens to whatever comes out of your speakers, like a real VU meter: Spotify, a YouTube tab, VLC or a game, nothing to configure
  • Make it bigger and it adds more bars rather than fatter ones
  • Long titles are cut to fit; title and artist stay centred
  • Only listens while a screen with a visualizer is on the LCD

📊 Live stats and a clock on L1

Press L1 to switch between the stats screen (CPU, temperature, VRAM, RAM) and a clock with the date and an analog face. Sensors are found by driver name, so most PCs need no setup:

  • CPU: AMD, Intel, VIA, ARM / Raspberry Pi
  • GPU: AMD, NVIDIA (proprietary driver via NVML, or nouveau), Intel Arc
  • Motherboard: Gigabyte, ASUS, Dell, ThinkPad, HP and most Nuvoton, ITE, Winbond, Fintek and SMSC chips
  • Anything your PC doesn't have shows N/A. src/g510_lcd_stats --sensors shows what was found

🌈 Backlight and ⌨️ G-key macros

The Backlight + G-Keys tab shows the whole keyboard in your current colour, with a live mirror of the LCD.

  • Colour from presets or a hex code: Apply now, or Set as Default for boot
  • Restored at every login and on every replug
  • Click a G-key to record a macro: keystrokes, or a shell command
  • M1 / M2 / M3 switch between three profiles of 18 macros, on the keyboard itself too
  • Save All Settings Now re-saves everything and reads it back from disk to prove it's there

What happens when…

A keyboard that drops off USB every time you touch the headset jack needs software that doesn't mind.

SituationWhat happens
You plug or unplug the headset jack (or the keyboard)The keyboard comes back as USB ID 046d:c22d (no headset) or 046d:c22e (headset); the udev rule matches both. The buttons listener and macro service reconnect in the same process (every 200 ms for 10 s, then every 3 s)
The LCD device is missingLogged once when it disappears and once when it's back, not on every frame
You reboot or log inThe services start at login; the backlight colour is restored at login and on every replug
No visualizer or media element is on screenNo audio capture and no playerctl calls at all
A media player hangsSong lookups give up after 2 s instead of freezing the LCD and the L-buttons
A song title is too longCut short with a . so it never runs off the screen
A sensor doesn't exist on your PCThat reading shows N/A; everything else keeps working
The bundled label font is missing or damagedA second bundled font is used, then the LCD library's built-in font. The LCD always starts
macros.json is damagedCopied aside (macros.json.broken-<time>) before anything is saved, and the app tells you where
Something unexpected goes wrong in the appThe error is logged and shown once; the app keeps running
The root-run backlight script reads your colour fileIt only parses brightness and RGB numbers (0–255), reads the file as you, and runs nothing from it
You re-run the installerIt only adds what's missing, and refuses to run as root

Install

Arch family (needs an AUR helper such as yay or paru) and Ubuntu 24.04 are tested. Other Debian-family distros should work the same way; Fedora and openSUSE are attempted but not tested yet.

Get it

git clone https://github.com/grumpybollocks/Logitech-G510s-LCD-control.git
cd Logitech-G510s-LCD-control

Run the installer as your normal user

It goes through 8 steps, prints [ok] or [missing] for every item as it goes and installs only what's missing; it asks for your sudo password once, and asks you to unplug and replug the keyboard once. Safe to re-run any time.

./install.sh            # --yes skips waiting for the replug

Check it worked

All three should say active (running). If the LCD stays blank, unplug and replug the keyboard once.

systemctl --user status g510-lcd-stats g510-lcd-buttons g510-macro-daemon

Open the app

From the G510 LCD - App shortcut on your desktop or in the app menu. If the installer added you to the input group, log out and back in first.

Needs: a recent kernel with the hid-lg-g15 driver, PipeWire with pipewire-pulse for the visualizer, any desktop. Where a distro doesn't package libg15/libg15render 1.3.1 or a new enough ydotool (1.0.4), the installer builds them into /usr/local from checksum-pinned releases. It also remaps the keyboard's Stop media key to Play/Pause (see the README to undo). Full list: README → Install.

How it works

Three small programs run as systemd --user services; the app is the editor.

g510-lcd-statsC. Draws every LCD screen and sends it to /dev/g510-lcd (hidraw).
g510-lcd-buttonsC. Listens to L1–L5 on /dev/g510-keys and switches screens.
g510-macro-daemonPython. Listens to G1–G18 and M1–M3 and replays macros through ydotool.
G510s Control appPyQt5. Backlight, macros and the Custom Screens builder; previews come from the LCD program itself.
udevStable /dev/g510-lcd and /dev/g510-keys links, whatever device numbers this boot gives.

Your settings (custom screens, images, macros, boot colour) live in ~/.local/share/g510-lcd, not in the checkout.

FAQ

Does it work with the original G510 or only the G510s?

Both: the G510 and the G510s, with or without a headset plugged in.

Will my media and volume keys still work?

Yes. The keyboard stays with the kernel's own hid-lg-g15 driver; the LCD is written through hidraw without detaching anything. One change: the installer makes the Stop key send Play/Pause. Delete /etc/udev/hwdb.d/91-g510-stop-to-playpause.hwdb and run sudo systemd-hwdb update to get Stop back.

The LCD stays blank after installing.

Unplug and replug the keyboard once so the new udev rules apply, then check the three services with systemctl --user status g510-lcd-stats g510-lcd-buttons g510-macro-daemon.

A temperature shows N/A.

Run src/g510_lcd_stats --sensors to see what was found. Many motherboards need their sensor driver loaded: sudo sensors-detect and load what it suggests (often sudo modprobe nct6775). Intel integrated graphics have no temperature sensor at all.

Does the visualizer only work with one music app?

No. It listens to whatever your speakers play, so Spotify, a browser tab, VLC or a game all work, with nothing to configure.

Do I need to save in the app?

No. Every change is written to disk immediately. Save All Settings Now exists to prove it: it re-saves and reads everything back.

Is it on the AUR?

Not yet. A PKGBUILD lives in packaging/; for now install with ./install.sh.
